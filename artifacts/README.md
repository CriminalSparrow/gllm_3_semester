# ДЗ: консультант автосервиса

Основной файл — **[autoservice_sft.ipynb](autoservice_sft.ipynb)** с выполненными ячейками и сохранёнными outputs. Отчёт — **[REPORT.md](REPORT.md)**.

Модель: `Qwen/Qwen2.5-1.5B-Instruct`, дообучение QLoRA на одной **Tesla T4**. Набор: 112 train / 16 validation / 20 test. Данные синтетические, без персональных данных; опасные учебные ответы отредактированы до обучения. API запрашивался как `glm-4.7`, фактическое поле модели в ответах — `glm-5.3-flash`. Подробности и ограничения — в отчёте.

## Запуск в Colab

1. Открыть ноутбук в Google Colab. **Среда выполнения → Сменить среду выполнения → T4**.
2. Для просмотра уже выполненного эксперимента достаточно открыть ноутбук: ответы, таблицы и графики сохранены. Для воспроизведения выполнить ячейки сверху вниз. Все импорты находятся в одной ячейке сразу после `pip install`.
3. При `RUN_TRAINING=True` скрипт заново получит исходные ответы, обучит адаптер, загрузит его с диска и получит ответы после обучения. Дождаться `EXPERIMENT_COMPLETE`. Повторный запуск записывается отдельно в `review_run/`; таблицы и примеры отчёта используют зафиксированный первый прогон. Отдельные ответы при повторном обучении на GPU могут немного отличаться. Данные, код и сохранённые оценки судьи включены в ноутбук. База скачивается с Hugging Face, нужен интернет.
4. При `RUN_JUDGE=False` используются реальные оценки первого API-прогона; код проверяет точное совпадение вопросов и ответов. Для новых ответов включить `RUN_JUDGE=True`, ввести URL API и ключ. По умолчанию запрашивается `glm-4.7`; фактическое имя модели сохраняется из ответа провайдера. Ключ вводится скрыто и не сохраняется.
5. Последняя ячейка создаёт архив результатов. Для скачивания в Colab установить `DOWNLOAD=True`.

Colab, использованный для запусков: [RK-1-GLLM-Sokolov-Egor](https://colab.research.google.com/drive/1BbetvzHhbHKYZ1x_teLpfMOPzw_t430D). Основной сдаваемый файл с выполненными ячейками — `autoservice_sft.ipynb` в этом репозитории.

Загрузка данных:

```python
from datasets import load_dataset
ds = load_dataset('json', data_files={
    'train': 'data/train.jsonl',
    'validation': 'data/validation.jsonl'
})
print(ds['train'][0]['messages'])
```

Для отдельного запуска скриптов из родительской папки `artifacts`:

```bash
pip install -r artifacts/requirements.txt
python artifacts/code/common.py
python -u artifacts/code/run_experiment.py   # только T4
python -u artifacts/code/judge.py            # опционально, требует API
python artifacts/code/plot_results.py
python artifacts/code/infer.py --question "На ходу загорелась красная лампа давления масла. Что делать?"
```

API-переменные: `LLM_URL` (base URL без `/chat/completions`), `LLM_TOKEN`, `JUDGE_MODEL=glm-4.7`. Их можно задать через окружение или `.env` рядом с `artifacts`. **`.env` не входит в сдаваемый комплект.** Для повторного сбора синтетических данных есть `code/prepare_data.py`; в обычном воспроизведении используются зафиксированные JSONL.

## Состав репозитория и Git

Сдаваемый комплект — корневой README, `.gitignore` и вся папка `artifacts/` с отчётом, выполненным ноутбуком, кодом, данными, весами LoRA, метриками, графиками и тремя JSON-логами. Отдельный ZIP не требуется; его копия удалена. Секреты, виртуальное окружение и кэши в репозиторий не входят.

В Git нужно добавить корневые `README.md`, `.gitignore` и **всю `artifacts/`**. Веса `adapter_model.safetensors` (~35 МиБ) и outputs ноутбука намеренно не исключены. `.env`, `.venv/`, архив и промежуточные checkpoints исключены в корневом `.gitignore`. Отчёт редактируется вручную; сборка ноутбука его не перезаписывает.

Адаптер загружается через `PeftModel.from_pretrained(base_model, 'artifacts/adapter')`, где `base_model` — указанная в `config.json` ревизия Qwen в NF4. Полный пример загрузки и генерации находится в `code/run_experiment.py`. Базовые веса не дублируются в архиве; [официальная модель](https://huggingface.co/Qwen/Qwen2.5-1.5B-Instruct) доступна публично.
